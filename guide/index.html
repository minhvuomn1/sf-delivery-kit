sf-kit: Hướng dẫn sử dụng

Bộ công cụ chuẩn hóa dự án Salesforce kết hợp Claude Code. Chạy một lệnh trong thư mục dự án có sẵn, kit thêm thư mục tài liệu (BRD, FSD, UAT, thư mục theo cloud), skill, agent, lệnh Claude Code và cấu hình MCP, rồi chọn skill theo tài liệu của dự án.

1. Tổng quan

Thành phầnLàm gì
sf-kit initThêm .claude/, docs/, CLAUDE.md, .mcp.json vào dự án có sẵn. Không ghi đè file đã có.
sf-kit detectQuét docs/brd, docs/fsd, docs/00-overview.md bằng từ khóa, đề xuất hoặc bật cloud và skill.
/setup-skillsLệnh trong Claude Code. Agent đọc tài liệu (kể cả PDF/docx) hoặc NotebookLM, ghi kế hoạch, chờ bạn xác nhận rồi bật skill.
add-cloud, install, listThêm cloud, bật một skill cụ thể, xem trạng thái.

Skill của kit nằm trong .claude/skill-catalog/ (Claude Code không tự nạp). Skill được bật sẽ copy sang .claude/skills/. Danh sách và lý do bật được ghi trong .claude/skills.lock.json.

2. Yêu cầu

  • Node.js 18 trở lên (node -v). Kit không dùng gói npm ngoài.
  • Dự án Salesforce có sẵn (có sfdx-project.json). Thư mục trống thì thêm --with-template.
  • Claude Code để dùng /setup-skills và các lệnh khác.
  • Salesforce CLI (sf) cho các skill deploy và MCP Salesforce.

3. Cài đặt

Chọn một trong ba cách. Cách 1 và 2 đều không cần npm.

Cách 1. Clone kit rồi chạy bằng node (khuyến nghị trên Windows)

git clone https://github.com/minhvuomn1/sf-delivery-kit.git D:\tools\sf-delivery-kit
cd D:\OMN1\ten-du-an
node D:\tools\sf-delivery-kit\bin\sf-kit.mjs init --clouds mce

Sau init, các lệnh còn lại chạy bằng node .claude\kit\kit.mjs <lệnh>, không cần đường dẫn kit.

<KIT> là gì? Là đường dẫn tới thư mục kit trên máy bạn, tức thư mục có package.json và thư mục bin\ bên trong. Đây là thư mục khác với dự án cần thêm kit; không chạy init bên trong thư mục kit. 
:: kiểm tra đúng thư mục: phải thấy sf-kit.mjs
dir D:\tools\sf-delivery-kit\bin

:: ví dụ đầy đủ (chạy ở thư mục dự án)
cd D:\OMN1\ten-du-an
node D:\tools\sf-delivery-kit\bin\sf-kit.mjs init --clouds mce

:: đường dẫn có dấu cách thì bọc nháy kép
node "D:\OMN1\my folder\sf-delivery-kit\bin\sf-kit.mjs" init
Nếu giải nén từ zip, thư mục kit có thể nằm lồng một cấp, ví dụ D:\OMN1\sf-delivery-kit-v1.5.1\sf-delivery-kit. Mẹo: trong File Explorer mở thư mục bin, bấm vào thanh địa chỉ để copy đường dẫn, rồi thêm \sf-kit.mjs vào cuối.

Cách 2. Cài từ git như một dependency

npm install --save-dev git+https://github.com/minhvuomn1/sf-delivery-kit.git
npx sf-kit init
Cài từ thư mục cục bộ (npm install D:\...) từng gây lỗi EPERM mkdir 'D:\' trên Windows vì npm tạo symlink. Cài từ git URL chưa được thử trên Windows; nếu lỗi, quay lại cách 1.

Cách 3. Cài toàn cục

npm install -g git+https://github.com/minhvuomn1/sf-delivery-kit.git
sf-kit init

4. Bắt đầu nhanh

cd ten-du-an
node <KIT>\bin\sf-kit.mjs init                 # 1. thêm khung kit, bật skill core
# 2. bỏ BRD/FSD (.md/.txt) vào docs\brd, docs\fsd
node .claude\kit\kit.mjs detect                    # 3. xem trước cloud/skill phát hiện được
node .claude\kit\kit.mjs detect --apply            # 4. bật và ghi docs\skill-plan.md
node .claude\kit\kit.mjs list                      # 5. kiểm tra

Trong các lệnh trên, <KIT> là đường dẫn thư mục kit (xem ví dụ ở mục 3, Cách 1). Rồi mở Claude Code ở thư mục dự án và chạy /setup-skills để agent rà lại, đặc biệt khi tài liệu là PDF/docx hoặc nằm trong NotebookLM.

Sau init nên commit .claude/, docs/, CLAUDE.md, .kit-version để cả team dùng chung. Không commit token hay file .env*.

Dùng lệnh Claude thay cho lệnh node

Hầu hết thao tác có thể gõ trực tiếp trong Claude Code dưới dạng slash command. Chỉ cần chạy bằng node một lần cho mỗi máy để cài lệnh /sf-init:

node <KIT>\bin\sf-kit.mjs install-global

Lệnh này ghi sf-init.md vào thư mục lệnh cá nhân của Claude Code (~/.claude/commands, trên Windows là C:\Users\<tên>\.claude\commands), kèm đường dẫn kit. Nếu bạn di chuyển thư mục kit, chạy lại. Sau đó, trong mọi dự án:

LệnhLàm gì
/sf-init [--clouds mce,sales-cloud] [--detect]Thêm kit vào dự án hiện tại (tương đương sf-kit init). Chạy một lần, rồi mở lại phiên Claude Code để thấy các lệnh dưới đây.
/setup-skillsĐọc BRD/FSD hoặc NotebookLM, đề xuất cloud và skill, chờ bạn xác nhận rồi bật.
/add-cloud mceThêm một cloud (tài liệu docs/<cloud>/ và skill kèm theo).
/mockup SCR-01 hoặc /mockup listFilterTable orderList "Đơn hàng"Dựng mockup thật cho một màn hình: LWC + App Page + Tab trong app Mockup. Claude tạo file và chờ bạn xác nhận trước khi deploy.
/mockup-app rename "Đặt hàng", /mockup-app split OrderApp orderList,approvalsĐổi tên app Mockup hoặc kéo màn hình ra app riêng.
/kit-statusXem cloud và skill đang bật.
/journey, /tdd, /review, /validate, /new-feature, /handoverCác lệnh quy trình có từ trước.

Các lệnh này khai báo sẵn quyền chạy node .claude/kit/kit.mjs nên không hỏi lại từng lần. Deploy lên org luôn cần bạn xác nhận. Quyền ghi của lệnh nằm trong dòng allowed-tools ở đầu mỗi file trong .claude/commands/, bạn có thể xem và chỉnh.

5. Tham chiếu lệnh

Có hai điểm vào: sf-kit (từ kit, dùng cho init) và .claude/kit/kit.mjs (nằm trong dự án, dùng cho mọi lệnh khác).

LệnhMô tả
init [--clouds a,b] [--all-skills] [--detect] [--with-template]Khởi tạo. --clouds: cloud đã biết. --all-skills: bật toàn bộ skill. --detect: quét và bật luôn. --with-template: copy thêm source mẫu (chỉ cho thư mục trống). Chạy lại an toàn.
detect [--apply]Không có --apply: chỉ in kết quả. Có --apply: bật cloud/skill đủ bằng chứng và ghi docs/skill-plan.md.
add-cloud <cloud...>Sinh docs/<cloud>/ và bật skill của cloud. Không ghi đè tài liệu đã có.
install <skill...> [--reason "..."]Bật skill từ catalog, ghi lý do vào lock.
listCloud đã bật, cloud có sẵn, skill [x] đang bật / [ ] chưa bật.
registryIn skill-registry.json (agent dùng để khớp tín hiệu).
mockup add <template> <tênMànHình> [--label ".."]Tạo màn hình thật trong source dự án (LWC + App Page + Tab), gắn vào app Mockup và permission set Mockup_Access, in lệnh deploy. Xem mục 9.
mockup rename --label ".." / mockup split <App> --screens a,b / mockup templatesĐổi tên hiển thị app, kéo màn hình ra app riêng, liệt kê template.

6. /setup-skills

  1. Agent đọc docs/brd, docs/fsd, docs/00-overview.md. Nếu có MCP NotebookLM thì hỏi thêm notebook theo 6 câu chuẩn.
  2. Lập bảng tín hiệu: tín hiệu, loại, trích dẫn ngắn, nguồn. Tín hiệu chung chung phải có từ 2 chỗ độc lập trở lên hoặc được hỏi lại.
  3. Khớp với registry, ghi docs/skill-plan.md gồm: đã bật (core), đề xuất, cần xác nhận, skill ngoài kit.
  4. Dừng và hỏi bạn. Chỉ sau khi bạn đồng ý mới chạy add-cloud / install.
  5. Cập nhật dòng cloud trong CLAUDE.md, nhắc commit.

Skill ngoài kit được tìm bằng skill find-skills (npx skills find). Agent chỉ đề xuất, không tự cài.

Lệnh liên quan: /add-cloud <cloud>, /journey, /tdd, /review, /validate, /new-feature, /handover.

7. Cloud có sẵn trong kit

Kit hiện có 5 cloud profile. Cột "Trạng thái" cho biết mức độ tin cậy của từng cái.

IDSinh raSkill kèm theoTrạng thái

service-clouddocs/service-cloud/: case-lifecycle, sla-entitlement, channels-knowledgekhôngChỉ có template tài liệu
experience-clouddocs/experience-cloud/: site-map, user-access, branding-themeexperience-cloud, frontend-designSkill là của team (có từ kit v1.0 và v1.3); template tài liệu mới

manufacturingdocs/manufacturing/: sales-agreements, forecasting, rebates, run-ratemanufacturing-cloudBẢN MẪU starter v0.1
Cloud MCE (và Manufacturing) là bản mẫu. Template tài liệu và skill mce-development được viết từ kiến thức chung để làm khung, chưa được kiểm chứng với tài liệu Salesforce hiện hành và chưa có người có kinh nghiệm MCE review. Danh sách mục trong docs/mce/ (Business Unit, Data Extension, Journey, Automation, MC Connect) là gợi ý, không phải chuẩn của team. Trước khi dùng cho khách: nhờ người làm MCE rà lại skill, sửa template cho khớp cách làm thật, rồi mới tăng phiên bản lên 1.0. Khi chạy add-cloud mce, kit cũng in cảnh báo này.

Mọi dự án đều có docs/brd/, docs/fsd/, docs/uat/, journeys/, decisions/, tasks/, traceability.md. Các cloud khác (Data Cloud, CPQ/Revenue Cloud, Field Service...) chưa có profile.

Thêm profile mới: tạo cloud-profiles/<tên>/profile.json (name, label, skills, folders, status: sample | template-only | team-skill) và thư mục docs/<tên>/ chứa template, rồi thêm mục trong claude/skill-registry.json.

8. Registry và mặc định

File claude/skill-registry.json (trong dự án: .claude/kit/skill-registry.json) quyết định:

  • core: skill luôn bật khi init. Gồm salesforce, salesforce-developer, mockup-prototype, journey-mapping, tdd-workflow, code-review, debug-workflow, jira-to-code-workflow, deploy-checklist, apex-conventions, apex-test-generator, lwc-patterns, sf-platform-gotchas, find-skills, project-skill-sync. Các lệnh /tdd, /review, /validate, /new-feature cần những skill này.
  • clouds: từ khóa nhận diện từng cloud.
  • conditional: từ khóa bật skill lẻ (kèm also cho skill đi cùng).
  • generic: từ khóa dễ trùng nghĩa (case, lead, portal...). detect chỉ tự bật khi có ít nhất 1 từ khóa đặc thù hoặc ít nhất 3 từ khóa khác nhau.
Skill salesforce là skill của Membrane (cần tài khoản Membrane), không phải skill phát triển Apex/LWC. Nếu không dùng Membrane, bỏ nó khỏi core.

Mockup là code thật, gom trong app "Mockup"

Mockup không nằm trong thư mục riêng. Mỗi màn hình là một LWC thật trong source dự án (force-app/main/default/lwc), kèm App Page và Tab, và tất cả được gom trong một Lightning App tên Mockup dùng dữ liệu giả qua c/mockDataProvider. Template nằm ở .claude/kit/mockup-templates/ (listFilterTable, multiStepForm, kpiDashboard, approvalPanel, portalLayout) và không bị deploy.

node .claude\kit\kit.mjs mockup templates
node .claude\kit\kit.mjs mockup add listFilterTable orderList --label "Đơn hàng" -o <alias-sandbox>
node .claude\kit\kit.mjs mockup add approvalPanel approvals

mockup add <template> <tênMànHình> làm các việc sau:

  • Copy template vào lwc/<tênMànHình>, đổi tên file và định danh bên trong (kể cả test Jest), đồng bộ apiVersion theo sourceApiVersion của dự án.
  • Tạo App Page Mockup_<tênMànHình> và Tab cùng tên, gắn vào app Mockup và permission set Mockup_Access.
  • Lần đầu còn tạo app, permission set và mockDataProvider. Chạy lại cho màn hình khác; không ghi đè file đã có hay đã sửa. tênMànHình phải là camelCase.
  • In sẵn lệnh deploy đúng các metadata vừa tạo (dạng sf project deploy validate -m "LightningComponentBundle:orderList" -m "FlexiPage:Mockup_orderList" ...) và lệnh sf org assign permset -n Mockup_Access.

Sau khi deploy, mở App Launcher và chọn app "Mockup". Demo theo docs/demo-script.md, ghi trạng thái từng màn hình (Mock/Thật) vào docs/screens.md. Cũng có thể nhờ Claude Code: "dựng mockup cho SCR-01" (skill mockup-prototype dựa trên docs/journeys/ và docs/screens.md).

Khi làm chính thức

Không cần di chuyển file vì mọi thứ đã nằm trong source dự án.

node .claude\kit\kit.mjs mockup rename --label "Đặt hàng"                                  :: đổi tên hiển thị của app
node .claude\kit\kit.mjs mockup split OrderApp --screens orderList,approvals --label "Order"   :: kéo màn hình ra app riêng

rename chỉ đổi tên hiển thị (API name vẫn là Mockup). split tạo app mới cùng permission set OrderApp_Access và gỡ các màn hình đó khỏi app Mockup; tab và App Page vẫn giữ tên Mockup_<màn hình> (tên nội bộ, người dùng không thấy). Sau đó thay dần thân hàm trong mockDataProvider bằng Apex thật, giữ nguyên chữ ký.

Metadata của app, tab, App Page và permission set được sinh theo định dạng Salesforce nhưng chưa được thử deploy trên org thật. Luôn chạy deploy validate trước; nếu có lỗi (ví dụ giá trị motif của tab, template của App Page), gửi thông báo lỗi để sửa. Chỉ deploy mockup lên sandbox. Cần **/__tests__/** trong .forceignore để test Jest không bị deploy (lệnh sẽ cảnh báo nếu thiếu). Dự án đã chạy init bản cũ: xóa thư mục prototype/ và dòng { "path": "prototype" } trong sfdx-project.json nếu có.

10. NotebookLM (tùy chọn)

claude mcp add notebooklm -- npx notebooklm-mcp@latest

Sau đó nhờ Claude chạy setup_auth để đăng nhập Google một lần, rồi /setup-skills --notebook <tên>.

  • Đây là MCP cộng đồng (PleasePrompto/notebooklm-mcp), không phải của Google hay Anthropic, điều khiển trình duyệt bằng tài khoản Google của bạn.
  • Thử trước, rồi pin phiên bản thay cho @latest.
  • Chỉ nạp tài liệu khách hàng nếu hợp đồng cho phép dữ liệu đi qua Google.
  • Kit chưa được thử với notebook thật.

Các MCP khác (Salesforce DEV/UAT, Jira, Playwright) cấu hình trong .mcp.json, hướng dẫn thiết lập máy ở docs/mcp-setup.md.

11. Workflow hằng ngày

Yêu cầu → /journey → mockup → /tdd → /validate → /review → PR. Cuối phiên chạy /handover.

ID truy vết xuyên suốt: J-xx → SCR-xx → BR-xx → test → ticket, ghi trong docs/traceability.md. Business rule do agent suy ra phải đánh dấu "(đề xuất - cần xác nhận)" cho đến khi người phụ trách nghiệp vụ chốt.

FSD đổi phạm vi hoặc thêm cloud: chạy lại detect hoặc /setup-skills. Kit không tự gỡ skill; skill hết bằng chứng chỉ được báo "có thể gỡ".

12. Nâng cấp kit

  1. git pull trong thư mục kit (hoặc cập nhật dependency).
  2. Trong thư mục dự án chạy sf-kit upgrade --pull --dry-run để xem trước, rồi chạy sf-kit upgrade --pull (--pull = git pull --ff-only trong thư mục kit trước; thiếu cờ này lệnh không tự pull). Không dùng lại init, vì init không ghi đè file đã có.
  3. Skill, agent, command và .claude/kit/ được ghi đè theo kit (bản cũ lưu ở .claude/.upgrade-backup/); skill có tiền tố project- được giữ nguyên.
  4. CLAUDE.md được gộp 3 chiều: không xung đột thì ghi thẳng, có xung đột thì ghi CLAUDE.md.new có dấu <<<<<<< để bạn xử lý. .claude/settings.json không bị ghi đè, lệnh ghi bản .new để gộp tay.
  5. Trong Claude Code có thể gõ /sf-kit upgrade --pull (cài một lần bằng install-global, cài lại để có lệnh mới): lệnh chạy dry-run trước, hỏi xác nhận rồi mới áp dụng.
  6. Lệnh in CHANGELOG từ .kit-version của dự án đến bản mới và cập nhật .kit-version.

14. Giới hạn đã biết

  • detect chỉ khớp từ khóa, không hiểu ngữ cảnh. Kết quả cần được người rà lại, hoặc dùng /setup-skills.
  • Kit đã được thử trên Linux; trên Windows mới có phản hồi về lỗi npm ở trên.
  • Hook pre-push deploy của kit (scripts/deploy-changes.sh) chỉ có trong project-template, không được copy vào dự án có sẵn.
  • MCE không deploy bằng sf CLI. Tài liệu trong docs/mce/ là nguồn truy vết chính.
  • NotebookLM MCP chưa được kiểm thử với notebook thật.
